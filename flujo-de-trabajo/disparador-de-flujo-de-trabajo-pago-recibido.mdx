## Disparador de flujo de trabajo: Pago recibido

<Info>
  **Documentado el 16 de agosto de 2026.**

  Artículo original modificado el martes, 2 de mayo de 2023 a las 5:59 a. m.
</Info>

El activador de **Pago Recibido** está diseñado para funcionar como un mecanismo centralizado que registra todos los pagos entrantes en el CRM, incluyendo compras únicas, cargos de suscripción, facturas y más. Se puede personalizar con filtros, como el tipo de origen y el estado de la transacción, para casos de uso específicos. Este activador ayuda a las empresas a automatizar tareas, optimizar procesos y responder de manera eficiente a las transacciones de los clientes en tiempo real.

## ¿Qué es el activador de flujo de trabajo de pago recibido y qué función cumple?

El activador "Pago recibido" automatiza procesos y acciones en función de los pagos entrantes cuando se utiliza en un flujo de trabajo. Se puede configurar para que responda a eventos de pago específicos, como transacciones exitosas o fallidas, o productos y fuentes de pago particulares.

**Cómo leer esta tabla:** cada fila se construye de izquierda a derecha. Eliges primero el **Filtro** (por ejemplo Payment Source), luego una de sus **Opciones** (Invoice), después el **Subfiltro** disponible para esa opción (Sub-Source) y por último el valor concreto (Text2Pay link). El operador siempre es _is_ o _is not_.

**Ejemplo:** para que el flujo se dispare únicamente con los cobros automáticos de una suscripción vendida en un embudo, la combinación es `Source is Funnel` \+ `Transaction type is Customer not present/subscription transaction` \+ `Payment Status is Success`.

## Preguntas frecuentes

<AccordionGroup>
  <Accordion title="¿Este mecanismo de activación incluirá también los pagos de suscripción posteriores?">
    Sí, el activador se ejecutará siempre que se reciba un pago del cliente final directamente al enviar un formulario de pedido y también cuando la suscripción se cobre en segundo plano.
  </Accordion>

  <Accordion title="¿Cómo puedo lograr el desencadenante para que las transacciones de suscripción posteriores se realicen con éxito?">
    Dado que las suscripciones se pueden crear en un embudo o en un sitio web, podemos crear un activador de Payment Received y aplicar los siguientes filtros para lograr el caso de uso: el tipo de fuente es **Funnel/Website** y el tipo de transacción es **"Customer not present/subscription transaction"**.

    El filtro de estado de pago (Payment Status) permite filtrar pagos exitosos o fallidos según el caso de uso.
  </Accordion>

  <Accordion title='¿Qué significan "Cliente presente/primera transacción" y "Cliente no presente/transacción de suscripción"?'>
    Las transacciones se clasifican en dos categorías:

    - **Customer present / first transaction:** incluye las transacciones en las que el cliente final está en sesión realizando el pago. Comprende todas las compras únicas y el primer pedido de un producto de suscripción.
    - **Transacción sin presencia del cliente / transacción de suscripción:** incluye los tipos de transacción que se ejecutan en segundo plano después de que se haya creado una suscripción. Por ejemplo, si un cliente compra un producto recurrente con un período de prueba de 14 días, la transacción realizada al comprar el producto recurrente (transacción de $$0 en este caso) se clasificaría como transacción con presencia del cliente / primera transacción. Después de 14 días, cuando finaliza el período de prueba y se cobran $$100 por el producto recurrente, la transacción de \$100 se clasificaría como transacción sin presencia del cliente / transacción de suscripción.
  </Accordion>

  <Accordion title="¿Los pagos fallidos también se incluirán en este activador?">
    Sí, por defecto, sin filtros, el activador se ejecuta tanto en intentos de pago exitosos como fallidos. Para casos de uso específicos relacionados únicamente con pagos exitosos o fallidos, podemos aplicar el filtro "Estado de la transacción" y configurarlo como exitoso o fallido según el caso.
  </Accordion>

  <Accordion title="He configurado el disparador y seleccionado un producto específico en los filtros. ¿Significa esto que el disparador se activará cuando se venda ese producto en cualquier lugar?">
    Si has configurado el activador y el filtro para un producto específico, este se ejecutará solo cuando dicho producto se venda en embudos de venta, sitio web o facturas. Mediante el filtro de estado de la transacción, podemos definir si el activador debe funcionar tanto si la compra es exitosa como si falla.
  </Accordion>

  <Accordion title="¿Qué es el filtro de subfuente?">
    Al seleccionar una fuente como embudos de venta, sitios web o facturas, estas pueden tener subfuentes. Por ejemplo, un pago proveniente del embudo puede provenir de un formulario de pedido de un paso, un formulario de pedido de dos pasos o una venta adicional. Puede usar estos filtros de subfuentes para definir el origen del pago.
  </Accordion>
</AccordionGroup>
