Las integraciones privadas te permiten conectar tu cuenta de Chateea con cualquier aplicación externa, mediante un token que tú generas y cuyos permisos tú decides.

## Cuándo la necesitas

Si quieres conectar tu cuenta con una aplicación externa, tienes dos caminos:

<CardGroup cols={2}>
  <Card title="Instalar una aplicación existente" icon="puzzle-piece">
    Buscas la aplicación en el marketplace y la instalas. No requiere desarrollo.

    Si existe, es siempre la opción más simple.
  </Card>

  <Card title="Crear tu propia integración" icon="code">
    Cuando no existe una aplicación para lo que necesitas, construyes la conexión tú o con un desarrollador, usando la API.

    Para eso están las integraciones privadas.
  </Card>
</CardGroup>

Sus dos ventajas principales:

- **Sencillez.** Generas y administras los tokens desde la configuración de tu cuenta, sin escribir código para obtenerlos.
- **Seguridad.** Defines exactamente a qué partes de tu cuenta puede acceder ese desarrollador o esa aplicación.

## Diferencia con las claves API

Las integraciones privadas son la alternativa moderna y más segura a las claves API tradicionales.

|  | Integraciones privadas | Claves API |
| --- | --- | --- |
| **Seguridad** | Restringes los permisos a los que puede acceder un desarrollador en tu cuenta | El desarrollador obtiene acceso sin restricciones a todos los datos de tu cuenta |
| **Tecnología** | Acceden a la API v2.0, la versión actual y mantenida | Funcionan con la API v1.0, que llegó al final de su ciclo de vida y ya no recibe mantenimiento |
| **Funciones** | La v2.0 es más potente y admite webhooks, que notifican a una aplicación externa cuando ocurre algo en tu cuenta | La v1.0 tiene funcionalidad limitada y no admite webhooks |

<Warning>
  Si todavía usas una clave API, migra a una integración privada. La v1.0 no recibe mantenimiento, y una clave filtrada expone **toda** tu cuenta sin que puedas limitar el daño.
</Warning>

## Diferencia con los tokens OAuth2

En pocas palabras: una integración privada **es** un token de acceso OAuth2, pero estático.

|  | Integraciones privadas | Tokens de acceso OAuth2 |
| --- | --- | --- |
| **Cómo se generan** | Desde la interfaz, en unos clics | De forma programática, intercambiando el código de autorización por el token mediante la API |
| **Vigencia** | Estáticos y fijos. No se renuevan solos: solo cambian si tú los rotas desde la interfaz | Caducan a diario y hay que renovarlos automáticamente |

<Tip>
  Por eso las integraciones privadas son la opción práctica para conexiones internas: no tienes que programar la lógica de renovación de tokens. Para una aplicación pública destinada a muchas cuentas, OAuth2 sigue siendo el camino correcto.
</Tip>

## Cómo se usa el token

El token viaja en el encabezado de autorización de cada petición, igual que cualquier otro token de acceso.

Ejemplo consultando un contacto:

```bash
curl --request GET \
  --url https://services.leadconnectorhq.com/contacts/ocQHyuzHvysMo5N5VsXc \
  --header 'Accept: application/json' \
  --header 'Authorization: <TU TOKEN DE INTEGRACIÓN PRIVADA>' \
  --header 'Version: 2021-07-28'
```

Tres elementos son obligatorios en cada llamada:

| Encabezado | Para qué sirve |
| --- | --- |
| `Authorization` | Tu token de integración privada |
| `Version` | La versión de la API que estás usando |
| `Accept` | El formato de respuesta que esperas |

<Warning>
  Si omites el encabezado `Version`, la petición falla. Es el error más común al hacer la primera llamada.
</Warning>

## Quién puede crearlas

Por defecto, **todos los administradores** de la cuenta pueden crear y gestionar integraciones privadas.

Puedes restringir ese permiso usuario por usuario en **Configuración → Mi personal → editar el administrador → Roles y permisos**, activando o desactivando **Integraciones privadas** para esa persona.

<Tip>
  Vale la pena restringirlo. Un administrador que puede crear tokens puede otorgar acceso a tus datos sin pasar por nadie más.
</Tip>

## Dónde encontrarlas

En **Configuración**, desplázate hasta la sección **Otras configuraciones** del menú lateral izquierdo.

<Note>
  Si no aparece la opción, verifica que la función esté habilitada en **Labs**.
</Note>

## Crear una integración privada

<Steps>
  <Step title="Pulsa Crear nueva integración">
    Desde la pantalla de integraciones privadas.
  </Step>
  <Step title="Ponle nombre y descripción">
    Para que tú y tu equipo identifiquen para qué sirve.

    Nombra por sistema, no por persona: `Sincronización con sistema contable` es mejor que `Integración de Juan`. Dentro de un año necesitarás saber qué se rompe si eliminas ese token.
  </Step>
  <Step title="Selecciona los permisos">
    Marca los ámbitos a los que quieres que esta integración tenga acceso en tu cuenta.

    <Warning>
      **Selecciona únicamente los permisos necesarios.** Si el sistema solo consulta contactos, no le des permiso de escritura ni de eliminación. El día que ese token se filtre, el daño queda limitado a lo que autorizaste.
    </Warning>
  </Step>
  <Step title="Copia el token generado">
    Y compártelo solo con el desarrollador de tu aplicación externa.

    <Warning>
      **El token se muestra una sola vez.** No podrás volver a verlo después. Cópialo y guárdalo en un lugar seguro en ese momento.

      Compártelo únicamente con personas de confianza y nunca de forma pública.
    </Warning>
  </Step>
</Steps>

## Rota tus tokens cada 90 días

Es la práctica recomendada para mantener la seguridad, incluso cuando no ha pasado nada.

Rotar significa generar un token nuevo dando un plazo para actualizar la aplicación externa antes de que el anterior deje de servir.

<Steps>
  <Step title="Abre la integración">
    En integraciones privadas, pulsa sobre la que creaste.
  </Step>
  <Step title="Elige Rotar y hacer caducar este token más tarde">
    Es la opción para rotación preventiva, sin urgencia.
  </Step>
  <Step title="Confirma la advertencia">
    Pulsa **Continuar** si estás seguro.
  </Step>
  <Step title="Copia el token nuevo y actualiza tu aplicación">
    Tienes **7 días** en los que **ambos tokens funcionan**, el viejo y el nuevo. Es el margen para que tu desarrollador haga el cambio sin que nada deje de operar.

    Durante esos 7 días puedes:

    - **Cancelar rotación**, si tu desarrollador necesita más tiempo
    - **Caducar ahora**, si la aplicación ya quedó actualizada con el token nuevo

    Pasados los 7 días, el token anterior caduca automáticamente.
  </Step>
</Steps>

<Note>
  Recuerda copiar el token nuevo en el momento: tampoco podrás verlo después.
</Note>

## Si tu token quedó expuesto

Aquí no hay periodo de gracia: se corta de inmediato.

<Steps>
  <Step title="Abre la integración afectada">
    En integraciones privadas, pulsa sobre ella.
  </Step>
  <Step title="Elige Rotar y caducar este token ahora">
    A diferencia de la rotación preventiva, esta opción **invalida el token anterior al instante**.
  </Step>
  <Step title="Confirma la advertencia">
    Pulsa **Continuar**.
  </Step>
  <Step title="Copia el token nuevo y actualiza tu aplicación">
    Cuanto antes, porque la integración está caída desde el momento en que rotaste.
  </Step>
</Steps>

<Warning>
  Úsala solo ante una sospecha real de exposición: token publicado en un repositorio, enviado por un canal inseguro, o en manos de alguien que ya no debería tenerlo. Todo lo que dependa de ese token deja de funcionar en el acto.
</Warning>

## Editar permisos sin cambiar el token

Puedes modificar el nombre, la descripción y los permisos de una integración en cualquier momento después de crearla.

<Steps>
  <Step title="Selecciona Editar">
    Desde el menú de tres puntos de la integración.
  </Step>
  <Step title="Actualiza nombre y descripción">
    Si hace falta. Pulsa **Siguiente**.
  </Step>
  <Step title="Ajusta los permisos">
    Marca o desmarca los ámbitos. Mantén el criterio de dar solo lo necesario. Pulsa **Actualizar**.
  </Step>
</Steps>

<Note>
  **Editar una integración no genera un token nuevo.** El token existente sigue funcionando, ahora con los permisos actualizados. No tienes que tocar tu aplicación externa.
</Note>

<Tip>
  Esto permite algo útil: empezar con permisos mínimos y agregar solo los que resulten necesarios, sin interrumpir nada.
</Tip>

## Eliminar una integración

Cuando dejes de usar la aplicación externa, elimina la integración desde el menú de tres puntos, opción **Eliminar**.

<Warning>
  Al eliminarla, el token deja de funcionar de forma permanente. Confirma antes qué sistemas lo están usando: si una sincronización corre en segundo plano, se detiene sin avisar a nadie.
</Warning>

## Buenas prácticas

<AccordionGroup>
  <Accordion title="Un token por sistema">
    No reutilices el mismo token en varios lugares. Si tienes que rotarlo o eliminarlo, quieres que caiga una sola cosa.
  </Accordion>

  <Accordion title="Nunca lo pongas en código público">
    Ni en un repositorio, ni en el código de tu sitio web, ni en nada que se ejecute en el navegador del usuario. Cualquiera puede leerlo ahí.
  </Accordion>

  <Accordion title="Guárdalo como variable de entorno">
    En el servidor que lo usa, nunca escrito directamente en el archivo del programa.
  </Accordion>

  <Accordion title="Compártelo por un canal seguro">
    Si tienes que dárselo a un desarrollador, usa un gestor de contraseñas, no WhatsApp ni correo.
  </Accordion>

  <Accordion title="Documenta cada integración">
    Qué sistema la usa, quién la mantiene y qué hace. Un token sin dueño conocido es un riesgo que nadie se atreve a eliminar.
  </Accordion>

  <Accordion title="Revisa la lista cada seis meses">
    Y elimina lo que ya no se usa.
  </Accordion>
</AccordionGroup>

## Solución de problemas

<AccordionGroup>
  <Accordion title="Error de autorización">
    El token está mal copiado, fue rotado o eliminado, o le falta el permiso para esa operación concreta.
  </Accordion>

  <Accordion title="Funciona para leer pero no para escribir">
    Falta el permiso de escritura en esa área. Lectura y escritura son permisos independientes. Edítalos sin necesidad de generar un token nuevo.
  </Accordion>

  <Accordion title="La petición falla sin mensaje claro">
    Verifica que estés enviando el encabezado `Version`. Sin él, la llamada no se procesa.
  </Accordion>

  <Accordion title="Dejó de funcionar de golpe">
    Revisa si alguien rotó o eliminó el token, si pasaron los 7 días de una rotación pendiente, o si la cuenta cambió a un plan que no incluye esta función.
  </Accordion>

  <Accordion title="No veo la opción en Configuración">
    Busca en la sección **Otras configuraciones** del menú lateral. Si sigue sin aparecer, habilita la función en **Labs**, o confirma que tu usuario tenga el permiso activado.
  </Accordion>
</AccordionGroup>
