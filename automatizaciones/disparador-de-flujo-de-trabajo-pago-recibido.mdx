title: "Disparador: Pago recibido"
description: "Automatiza confirmaciones, avisos y recuperación de pagos con cada pago exitoso o fallido en tu cuenta."

---

El disparador **Pago recibido** (Payment Received) inicia un flujo de trabajo cada vez que entra un pago en tu cuenta de Chateea, venga de donde venga: compras únicas en embudos o sitios web, cobros de suscripciones, facturas, enlaces de pago por mensaje o reservas de calendario. Con sus filtros puedes limitarlo a un producto, un origen o un estado concreto (pago exitoso o fallido) y automatizar confirmaciones, avisos al equipo o la recuperación de pagos fallidos.

## Para qué te sirve

- **Confirmaciones automáticas:** envía al cliente un correo o mensaje en cuanto se procesa su pago.
- **Gestión de suscripciones:** actualiza el estado del cliente cuando un cobro recurrente sale bien o falla.
- **Recuperar pagos fallidos:** avisa a tu equipo o inicia una secuencia de recordatorios cuando un pago no pasa.
- **Segmentar clientes:** etiqueta a quienes compran mucho o con frecuencia para ofrecerles promociones.
- **Seguir tus ventas:** registra cada pago para analizar productos más vendidos y tendencias.
- **Conectar tu contabilidad:** envía los datos del pago a tu sistema contable con un webhook.

## Configurar el disparador

<Steps>
  <Step title="Agrega el disparador">
    En **Automatización → Flujos de trabajo**, abre o crea un flujo, haz clic en **Agregar disparador** y elige **Pago recibido**.
  </Step>
  <Step title="Agrega filtros">
    Haz clic en **Agregar filtro** para elegir un filtro. Vuelve a hacer clic en **Agregar filtro** para añadir subfiltros que lo afinen.
  </Step>
  <Step title="Guarda y agrega acciones">
    Guarda el disparador, agrega las acciones que quieras (mensajes, etiquetas, notificaciones) y publica el flujo.
  </Step>
</Steps>

Por ejemplo, para que el flujo se active solo con compras hechas en un formulario de pedido de dos pasos: **Origen del pago** → **es** → **Embudo / Sitio web**, luego **Agregar filtro** → **Suborigen** → **es** → **Formulario de pedido de dos pasos**.

## Filtros disponibles

| Filtro | Opciones | Subfiltro | Opciones del subfiltro |
| --- | --- | --- | --- |
| **Origen del pago** | Factura | Suborigen | Enlace de pago por mensaje (Text2Pay), factura única, plantilla recurrente |
| | Embudo / Sitio web | Suborigen | Formulario de pedido de un paso, formulario de dos pasos, upsell |
| | | Tipo de transacción | Cliente presente o primera transacción; cliente no presente o transacción de suscripción |
| | Calendario | Calendario | Nombres de tus calendarios |
| **Producto** | Productos de tu catálogo | Precio | Precios del producto elegido |
| **Estado del pago** | Exitoso, Fallido | | |

Todos los filtros usan los operadores **es** y **no es**.

### Tipos de transacción

- **Cliente presente o primera transacción:** el cliente está en la página pagando en ese momento. Incluye todas las compras únicas y el primer pago de una suscripción.
- **Cliente no presente o transacción de suscripción:** cobros que se hacen en segundo plano después de crear la suscripción.

Ejemplo con periodo de prueba: si un cliente contrata un producto recurrente con 14 días de prueba, el pago inicial de 0 al suscribirse es una transacción con **cliente presente**. Cuando termina la prueba y se le cobra automáticamente la cuota, ese cobro es una transacción con **cliente no presente**. Así puedes automatizar cada momento por separado.

## Condiciones Si/Entonces

Después de configurar el disparador, puedes crear ramas con la condición **Pago**:

| Opción | Operadores | Valores |
| --- | --- | --- |
| **Producto** | es, no es | Productos de tu catálogo |
| **Embudo / Sitio web** | es, no es | Nombres de tus embudos o sitios |
| **Calendario** | es, no es | Nombres de tus calendarios |
| **Origen** | es, no es | Factura, Embudo, Sitio web, Calendario |
| **Estado del pago** | es, no es | Exitoso, Fallido |
| **Importe** | Igual a, distinto de, mayor que, mayor o igual que, menor que, menor o igual que, está vacío, no está vacío | Importe pagado |

## Ideas de uso

- **Cobro de suscripción fallido:** filtra por **Estado del pago: Fallido** y **Tipo de transacción: cliente no presente** para enviar una secuencia de recordatorios y avisar a tu equipo.
- **Bienvenida a nuevos suscriptores:** filtra por **cliente presente** y un producto recurrente para enviar el acceso y las instrucciones.
- **Pagos por mensaje:** usa el suborigen de enlace de pago por mensaje (Text2Pay) para confirmar y agradecer los pagos que cobras por SMS.

## Preguntas frecuentes

<AccordionGroup>
  <Accordion title="¿Qué es el subfiltro de suborigen?">
    Indica el origen exacto del pago dentro de una fuente. Por ejemplo, un pago de un embudo puede venir de un formulario de pedido de un paso, de uno de dos pasos o de un upsell.
  </Accordion>
  <Accordion title="¿Se activa con el primer pago y con los siguientes cobros de una suscripción?">
    Sí. Se activa cuando el cliente paga en el formulario de pedido y también cada vez que se cobra la suscripción en segundo plano.
  </Accordion>
  <Accordion title="¿Cómo lo configuro solo para cobros recurrentes exitosos?">
    Usa **Origen del pago: Embudo / Sitio web**, **Tipo de transacción: cliente no presente o transacción de suscripción** y **Estado del pago: Exitoso**.
  </Accordion>
  <Accordion title="¿También detecta pagos fallidos?">
    Sí. Sin filtros, el disparador se activa con pagos exitosos y fallidos. Usa el filtro **Estado del pago** para quedarte solo con uno de los dos.
  </Accordion>
  <Accordion title="Si filtro por un producto, ¿se activa cuando se vende en cualquier lugar?">
    Se activa cuando ese producto se vende en embudos, sitios web o facturas. Combínalo con el filtro de estado para distinguir compras exitosas de fallidas.
  </Accordion>
</AccordionGroup>
